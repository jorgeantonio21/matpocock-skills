`idiomatic-rust`: close the gaps from the quality evaluation (fork issue #6). The preamble states the scope (a library, a service, or an engine) and each house rule now says where it does not apply: rejection-as-outcome, `Copy` errors, wire types, `new_const`, and the hot-path regime. `RUNTIME.md` decides async in a trait by dispatch (a sync seam in an engine, a native `async fn` trait behind `trait-variant` and `dynosaur` in a service with a pluggable backend), adds a `Send`-at-the-spawn-boundary entry, and says a work queue at the edge is an `mpsc`. New idioms: let chains (edition 2024), `impl Iterator` and `Cow<'_, str>` in return position ("Return by need"), and `#[non_exhaustive]`. Inconsistencies fixed: `Default` off the `JobId` derive stack, tests return `anyhow::Result<()>` everywhere, the sentence cap follows ASD-STE100 (20 for an instruction, 25 for a description), `-A unreachable_pub` for a binary crate, and a bounded newtype returns `Result` with the rejected value at a config or request boundary. `expect_used` leaves the check command and the workspace block, because `expect` with the invariant as its message is the form the skill asks for; `unwrap_used` stays.

The skill now ships an evaluation suite under `evals/`: five scenarios (write a crate, refactor a crate with thirteen planted drift patterns, extend a crate, write a tokio worker pool, review a crate), each with a prompt, a starting crate pinned to Rust 1.97.1, and a rubric naming the skill entries it exercises. `run.sh` runs a scenario headless in a bare arm and a skill arm on the same model; `score.sh` runs the tests, the LINTS.md check, and pattern counts on both trees. The first run (Fable 5.1) showed the skill's effect on the type-level rules and none on the mechanical ones, and five sentences the run showed to be no-ops or misfires were cut.
